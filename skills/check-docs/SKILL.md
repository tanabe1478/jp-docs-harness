`$ARGUMENTS`に対象が指定されている場合は、次を実行してください。

`${CLAUDE_PLUGIN_ROOT}`がシェルで未設定の場合は、このスキルのベースディレクトリの二階層上（プラグインルート）の絶対パスへ読み替えてください。環境変数を手動で設定する必要はありません。

```console
node "${CLAUDE_PLUGIN_ROOT}/scripts/claude-lint.mjs" --target "$ARGUMENTS"
```

指定がない場合、現在の依頼で対象のGitリポジトリまたはMarkdownが一件に絞れるなら、そのパスを`--target`へ渡してください。対象が明らかでなければ次を実行し、現在の作業ディレクトリが一つのGitリポジトリに属している場合だけ、そのリポジトリを検査します。

```console
node "${CLAUDE_PLUGIN_ROOT}/scripts/claude-lint.mjs"
```

複数リポジトリの親ディレクトリで対象を特定できない場合は、候補を示して利用者へ選択を求めてください。無関係なリポジトリをまとめて検査してはいけません。

既定では太字の使用そのものを警告します。利用者が太字を使う方針を示した場合だけ、`--bold moderate`（乱用のみ警告）または`--bold allow`（太字を検査しない）を追加してください。文書契約の`style.bold`がある文書では、そちらが優先されます。

利用者が読みやすさの推敲（長い文、二重否定、「の」の連鎖の確認）を求めた場合は`--reading-load`を追加してください。この指摘は情報レベルの指し示しで、修正するかは文意を確認しながら判断します。

AIが多用する語彙（「効く」「入口」など）は既定で検査され、情報レベルで指されます。指摘された語を機械的に置き換えるのではなく、「キャッシュが効く」のような正当な用法かを文脈で確認し、不自然な場合だけ言い換えてください。対象リポジトリの業務用語（製品名や定型の専門語）が辞書と衝突して指摘が大量に出る場合は、利用者へ伝えたうえで`--no-ai-words`を追加できます。

結果の表示は次の意味です。

- `[AIで修正可能]`: 文意を保てる範囲で修正できます
- `[書き手に確認]`: 推測で埋めず、利用者へ質問してください
- `[手作業で修正]`: 自動修正では文意を保てないため、必要な変更を利用者へ説明してください
- `[要確認]`: 不確実な理由を利用者へ伝えてください

AIで修正可能な指摘だけを一度修正し、同じ対象でコマンドを再実行してください。修正では文脈から分かる主語・目的語・条件を補わず、指摘された語は言い換えるより先に削れないかを検討してください。修正後の本文が修正前より長くなった場合は、増えた理由を利用者へ伝えてください。警告を消すために意味を薄めたり、ルールを無効化したり、許可リストへ追加したりしてはいけません。

修正により意味が変わる可能性がある指摘、書き手の入力が必要な指摘、再検査後も残る指摘は変更せず、利用者へ簡潔に伝えてください。

# コーディングエージェントへの依頼文

https://github.com/tanabe1478/jp-docs-harness に、ローカルWeb執筆アプリ「jp-docs Studio」のMVPを実装してください。

最初に添付した `jp-docs-studio-agent-handoff-v0.3.md` を全て読み、実装上の単一の基準として使ってください。製品思想の補足は `jp-docs-studio-concept-v0.1.md` にあります。画面仕様は `studio-visual-spec-v0.3.md`、スクリーンショットと静的HTML/CSSは `design/` にあります。**開発前にこれらを確認してください。**

最重要の目標は「AIが文章を代筆すること」ではなく、「書き手が静かな執筆空間で文章を書き、選択箇所についてAIと議論し、自分の考えを明確にできること」です。OmmWriterに着想を得た落ち着いた雰囲気は採用しますが、既存のUIや素材はコピーしないでください。

`studio/` を追加し、Markdownの編集と永続化、選択範囲からのAIとの対話、保留・却下・Insight記録、差分を承認して適用、既存の `check-docs` 実行までを実装してください。AI未設定でも執筆・保存が使え、偽のAI出力を表示しないこと。既存CLI/pi/Claude Codeプラグインを壊さず、スコープ外の機能を勝手に拡張しないでください。

作業開始時にリポジトリの現状を調べ、短い計画を示してください。Milestone A→B→Cの順で進め、各段階でテストを実行してください。最後に起動方法、画面キャプチャ、受け入れテストの成否、既知の課題を報告してください。APIキーや認証情報はコード・ログ・コミットに含めないでください。

画面は Focus → Discuss → Proposal の順に完成させ、既存の4枚の画面イメージをデザイン基準にしてください。デスクトップではAIパネルを開閉しても本文の行折り返し位置を変えないこと。`design/atmosphere-moodboard.png` は雰囲気の参考に過ぎず、描かれた追加機能を実装対象と誤認しないでください。静的HTML/CSSは参考であり、実際のMarkdown編集・保存・AI対話の動作を置き換えるものではありません。

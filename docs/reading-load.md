# 読解負荷レーン

`--reading-load`で有効になる読解負荷の検査です。AI臭さの検査（styleゲート、textlint preset）とは目的が別で、文章の下手さやAIらしさを測るものではありません。一文にどれだけ内容が詰め込まれているかを指し示し、推敲の見落としを防ぎます。

設計は[natural-japanese v1.4.0の読解負荷レーン](https://github.com/coji/natural-japanese)と[meiseki](https://github.com/bamboo-nova/meiseki)を参考にしています。

## 設計原則

- 指摘はすべてseverity `info`で、判定やスコアは出しません。`--fail-on warning`でもブロックしません
- 既定は無効です。`--reading-load`または文書契約の`style.reading_load: check`で有効になります
- 結果は他の検査と混ぜません。AI臭さの検査と読解負荷を同じ判定に混ぜると、どちらの判断も曖昧になるためです
- 検出器を追加してよいのは、読み流すと見落とすものだけです。読めば確実に気づくものへ検出器を足しても、指摘の件数が増えるだけで判断の質は上がりません

## 実装した検出器

| ruleId | 検出内容 |
| --- | --- |
| `readability/sentence-too-long` | 句点で終わる一文が、読み手が実際に読む文字で100文字を超える |
| `readability/double-negative` | 「なくはない」「ないわけではない」などの二重否定 |
| `readability/no-chain` | 名詞句を「の」で3回以上つないだ連鎖（こそあど言葉は除く） |

文字数はMarkdownの記法・URL・インラインコード・画像を除いて数えます。natural-japaneseでは、記法のマーカーを本文として数えたことが指摘の42%を占める誤検知になった事例があります。表の行とコードブロックは対象外です。

## 見送った検出器と理由

同じ検出器の追加が繰り返し提案されないよう、見送りの根拠を残します。

| 候補 | 見送りの理由 |
| --- | --- |
| 漢字の連続 | 「東京地方裁判所」のような固有名詞を誤検知する。除外には形態素解析が必要で、依存を増やしてまで入れる価値をまだ確認できていない |
| 埋もれた列挙（読点の数） | natural-japaneseで読点4個以上の閾値が文書の62%に反応した前例がある。列挙の構造判定には形態素解析が必要 |
| 「が」の連鎖 | natural-japaneseの校正で9,889文中1件しか出現しなかった前例がある。発生自体が稀 |
| 読解負荷スコア（meisekiのRLS） | 本リポジトリは複数次元を単一スコアへ集約しない方針のため採用しない。件数と位置の提示に留める |

## 校正の記録

- 2026-08-16: 「の」の連鎖のチャンクを漢字・カタカナ・英数字に限定した。当初の実装は「長文はAIの特徴ではなく人間の内容の」のように「ではなく」をまたいで別の名詞句を連鎖に数えていた。ひらがなを含む名詞の連鎖は取りこぼすが、誤検知を増やすより取りこぼす方を選んだ

## 閾値の根拠

一文100文字は、natural-japaneseが候補検証で使った「100字超え」に合わせた初期値です。同リポジトリのコーパス検証では、長文はAIの特徴ではなく人間の内容の詰まった文章にも現れると報告されています。だからAI臭さの検査には使えず、推敲の指し示しとしてだけ使います。運用で過剰・過少が分かったら、この文書へ記録を残して調整してください。
